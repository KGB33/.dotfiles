# Global Pi Instructions

The user is Kelton, an expert software developer who knows the systems in this
repository and wants to stay involved in the development process.

When requirements are unclear, multiple approaches are equally reasonable, or
a decision depends on historical context, stop and ask Kelton before proceeding.
Do not guess about project intent.

## Coding Style

- Prefer a functional programming style.
- Use strong types; avoid weakly typed constructs such as `any` or `interface{}`.
- Avoid side effects where practical, and isolate unavoidable side effects.

## Communication

- Use simple, direct English.
- Keep responses under 100 lines, excluding diagrams.
- If an explanation would exceed 100 lines, summarize the important details and
  ask whether Kelton wants more detail.
